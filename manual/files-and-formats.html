Files and exports

What the toolkit can export

Most tools are read-only: you type numbers and read numbers. Three produce files.

LC Matching Ladder exports a 2-port Touchstone .s2p (or a 1-port .s1p), plus HTML and plain-text summaries of the solved network.

PCB Design Wizard exports its report as HTML or Markdown.

Material Comparison links out to the manufacturer's datasheet PDF for each laminate via the Open ⇗ column — that opens in your browser rather than downloading through the app.

Touchstone files

A Touchstone file is the standard interchange format for frequency-domain S-parameters. The .s2p the LC Matching Ladder writes contains the solved network's S11, S21, S12 and S22 over the sweep band you set on the page, both ports referred to Z₀. The .s1p is the input reflection with your load attached.

Quality line. Every file carries a ! Quality screen … comment with the verdict of four checks: passivity, reciprocity, sampling and causality. Passivity is the largest singular value of S. Readers ignore comment lines, so the file is still standard. Until 2026-10 the .s2p's S11 column held the input reflection with the load attached. That mixed two different circuits, and the passivity check caught it. Files exported before then should be re-exported.

What to do with it. Import it into a circuit simulator (Qucs-S, ADS, Microwave Office, LTspice with an S-parameter block) to cascade the matching network with the rest of your chain, or into a VNA's analysis software to compare a measured prototype against the design.

One direction only. The toolkit writes Touchstone files; there is no Touchstone import. You cannot load a measured .s2p and have the ladder match to it. If you have a measured complex impedance, read the R and X at your frequency of interest and type them into the Zs / Zl fields.

What the toolkit cannot read

There is no CAD import of any kind. Specifically:

  • No Gerber, ODB++ or IPC-2581
  • No netlists
  • No Altium, KiCad, Eagle, OrCAD or Allegro project files
  • No stackup files from a fabricator
  • No IBIS or IBIS-AMI models
  • No Touchstone import

Every input is typed. This is a deliberate scope boundary, not a missing feature — the toolkit is a calculator set, and a layout parser is a different product.

The practical consequence: when a tool asks for a trace length or a stackup height, get that number from your CAD tool and type it in.

Settings and where they live

The desktop build stores its preferences in a small file under the per-user application data directory. There is no project file and no document model — tool inputs reset to defaults each time you open a tool.

The browser build stores nothing outside the tab. Closing it discards everything.

Nothing is uploaded. Neither build sends your inputs anywhere. The browser build in particular does all its computation inside the WebAssembly sandbox in your own tab; the only network traffic is fetching the application itself.

Copying results

Every output value is selectable text. For a full record of a calculation, the usual approaches are a screenshot, or — for the two tools that support it — the HTML/Markdown export.

There is no "export all results as CSV" across tools. If you need to sweep a parameter and tabulate the results, that is a manual loop.
