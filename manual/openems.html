The 3D field solver

What openEMS is

openEMS is a free, open-source FDTD (finite-difference time-domain) electromagnetic field solver. The toolkit's desktop build bundles it, so the Trace Impedance tool can extract a characteristic impedance from an actual simulated field rather than from a closed-form approximation.

For the impedance of a uniform line, the tool's in-process 2D field solver already does this in a fraction of a second, outside the closed forms' range too — very thick copper, very wide or very narrow traces, coplanar structures with tight gaps. The 3D solver is for what a 2D cross-section cannot see.

2D first, 3D second

The impedance tool answers in three tiers:

  1. Closed forms — Cohn (1955), Hammerstad-Jensen, IPC-2141 and Ghione-Naldi. Instant, but fits with validated ranges.
  2. The 2D field solver — a quasi-static solve of the cross-section that runs in-process (in the browser too) when you press Solve 2D, in 25–550 ms. For a uniform line's Z₀ and εeff it is the reference: within 0.3 % of Cohn's exact stripline and inside the spread of six commercial solvers on a published benchmark (see Verification and limits). The tool lists each closed form's difference from it.
  3. openEMS 3D FDTD — minutes per run, desktop only. A uniform line's impedance is a 2D problem, so for that number the 3D run adds nothing the 2D solver has not already given you. It earns its runtime on what a cross-section cannot show: the launch, discontinuities, frequency dispersion, radiation.

Use the closed forms' distance from the 2D answer as a confidence signal. When they agree within a fraction of an ohm, the geometry is well inside their range. When they disagree by several ohms, the 2D answer is the one to use — the broadside-coupled closed form, for instance, ignores the planes and can be tens of percent off on a tight stackup.

The practical workflow is: converge on a geometry with the 2D solver, then run the 3D solver once if a 3D effect matters. Running FDTD on every trial width wastes minutes for nothing.

The dielectric the 3D run is given is the one picked on the page: a bundled library material by name, anything else (the laminate builder, the RF catalog, a custom value) as a custom Dk — so all three tiers use the same Dk.

How the solver measures Z₀

The solver builds a straight length of your cross-section that runs out of both ends of the simulated box into absorbing layers, so nothing reflects back. A source near one end launches a wave down the line; at three planes further along (the first one at least twelve dielectric heights from the source, where the source's local fields have died away) it records the voltage between the trace and its reference plane and the current flowing in the trace. Z₀ is the ratio of the two for the forward-travelling wave, averaged over a frequency band chosen from your geometry so that the line is quasi-static (the same regime the closed-form formulas describe). The phase change between the planes gives the effective permittivity ε_eff.

Some details that matter for particular topologies:

  • Stripline voltages are measured to both planes and the source drives both gaps, so the solver never launches the plane-to-plane mode that a one-sided port excites.
  • Differential pairs are driven odd-mode (+1 V / −1 V); the result is the differential impedance, twice the odd-mode impedance.
  • CPWG coplanar grounds are tied to the bottom plane by via fences, modelled as continuous walls two dielectric heights outside the slots (the limit of a dense fence; the field there is negligible).
  • Dielectric loss (the laminate's Df) is included, and the tool reports the resulting attenuation.

If the engine fails, or the measured wave is not clean, the run reports an error. It never substitutes a closed-form number for a 3D result.

Sim quality

The Sim quality dropdown trades runtime against mesh resolution: Quick, Standard and High put 4, 6 and 10 cells across the thinnest dielectric and the narrowest trace or gap, and refine the grading away from the copper with them. On cross-sections with known exact answers the solver reads, against the exact value:

Quality Typical error (thin-copper stripline / microstrip) Typical runtime
Quick about −1.4 % / −0.9 % about 10 s
Standard about −0.6 % / −0.5 % 15–40 s
High about −0.4 % / −0.2 % 30 s – 3 min

The error comes from the knife-edge field at the copper edges and shrinks as the mesh refines. ε_eff of a homogeneous stripline comes out equal to Dk.

After a run the tool reports the extraction method it used, the solver's own analytic cross-check, and the mesh resolution that was actually applied — so you can see whether the mesh was fine enough for the feature sizes in your cross-section.

Before you run: the time estimate

As soon as the engine is found, and again after every change, the 3D card shows Before you run: the selected quality's cell count and expected run time, with the other two qualities' times beside it. The cells come from the run's own mesh rules (no simulation is started); the time is a fit to measured runs on the development PC (12 threads), so on another computer all three scale alike. Above about two minutes the card warns and names the quicker preset. Above the solver's limit of 12 million cells the Run button is disabled and the card names the finest quality that fits — usually a very narrow trace or gap over a thick dielectric; check the dimensions first.

Thick copper

A trace's thickness changes Z₀ and ε_eff, and the solver models it: the copper's side walls and corners are in the mesh. Where thick copper sits on the laminate's surface (microstrip, CPWG and their pairs), the cell just under each bottom corner is corrected for the corner's field, which the cell is too coarse to resolve; before that correction (2026-10-20) ε_eff of such lines read up to about 1.2 % high. Over trace width 0.5–4 × h and copper 0.1–0.5 × h, Standard is now within about ±0.5 % of a converged 2D solve in Z₀ and ε_eff. A microstrip's ε_eff from the 3D run sits about 0.2 % above the quasi-static value: that is the line's real dispersion at the pulse's frequency, not error.

Why it is desktop-only

The solver is a native compiled engine driven through a Python sidecar. Neither runs inside a browser sandbox. In the web build the 3D section is visible but disabled, with a banner explaining that 3D FDTD simulation runs locally only and a link to download the desktop app.

Everything else in the toolkit is identical between the two builds. The analytic impedance estimates, the 2D field solver and the laminate builder, and all 48 other tools, work exactly the same in the browser. The 2D solver is pure managed code, compiled ahead of time to WebAssembly, so a solve takes about the same time in the browser as on a desktop (a microstrip in roughly 0.1 s). It runs only when you press Solve 2D, so typing never waits on it; the browser runs it on its one thread, so a slow pair geometry may pause the page briefly while it solves.

What ships with the desktop installer

The Windows installer bundles a portable Python runtime, the openEMS native engine and its dependencies, and the sidecar script that connects them to the application. There is nothing to install separately and no PATH to configure — the application locates the bundled interpreter and engine relative to its own executable.

This is why the desktop download is substantially larger than a typical application: the solver and its Python stack account for most of it.

When the solver reports an error

The 3D section shows a diagnostic banner if the sidecar cannot start or exits without a result. The usual causes are an antivirus product quarantining the bundled native engine, or an installation that was moved rather than reinstalled so the relative paths no longer resolve. Reinstalling in place fixes both.

If you only need impedance numbers, the 2D field solver and the analytic path need none of this and always work.

What the solver does not do

It extracts characteristic impedance, ε_eff and dielectric attenuation for the transmission-line cross-sections the tool offers. Copper is a perfect conductor (no conductor loss, no surface roughness), and the laminate is one Dk and Df at all frequencies. It is not a general-purpose 3D EM workbench: it does not do S-parameter extraction over a full board, does not import your layout, does not simulate connectors or packages, and does not do time-domain channel simulation.

For a channel-level answer, use the Channel Insertion Loss Budget and Via Stub Impact tools, which are analytic and cover the whole link rather than one cross-section.
