How to read this page

Each benchmark compares a calculator with a reference it does not share code with — an exact solution, a published solver or measurement, a datasheet, or a standard's own equation — at a tolerance stated before the comparison. A tool's chip is PASS when every benchmark that checks it passes, FAIL when one has a failing check (every failure here is a known one: the math is kept for parity with the original toolkit, the tool now warns, and docs/validation/GAPS.md says what it would take), and GAP when nothing checks it yet. partial means part of the tool is still unchecked. Rows marked for information are shown but not gated.

The numbers are recorded by the test suite (scripts\validate.ps1); each benchmark carries a fingerprint of the code it came from, and the fast test suite fails when that code changes until the benchmark is recorded again.

Kinds of reference, strongest first:

  • exact (29) — a closed-form or analytic answer with no approximation, or a definition.
  • measured (1) — hardware on a network analyser.
  • published tools (5) — commercial or standard tools' results printed in a paper.
  • datasheet (2) — a vendor's published table or footprint.
  • independent tool (5) — another program run on the same input (SciPy, an independent solver).
  • validated solver (12) — the toolkit's own 2D field solver, itself within 0.3 % of exact answers on this page.
  • closed form (9) — an established engineering formula with a stated accuracy, or a published design equation.
  • self-consistency (1) — a model's own limits or identities.
